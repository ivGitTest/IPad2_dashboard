# Техническая справка: HomeDashboard

Справка по текущей реализации для передачи проекта другому разработчику/агенту.
Пользовательская инструкция — в `README.md`.

## 1. Назначение и контекст

Одностраничный веб-дашборд для **iPad 2** (характеристики — `ipad-2.md`):

- iOS 9.3.5 → движок WebKit уровня Safari 9 (Chrome на этом iOS использует тот же WebKit).
- Экран 1024×768, ландшафт; страница рассчитана ровно на этот размер, без скролла.
- Слабое железо (Apple A5, 512 МБ) → только лёгкие анимации.
- Режим использования: постоянно включённый экран-часы. Полноэкранный режим —
  только через Safari → «На экран "Домой"» (мета-тег `apple-mobile-web-app-capable`).

Отображает: **левая половина** — погода в локации из `config.json`
(город и координаты — настраиваемый параметр; иконка солнце/облака/дождь/снег,
температура, «ощущается», ветер, время обновления) и **внизу её — почасовой прогноз
на 4 ближайших часа** (час, маленькая иконка, температура), **правая половина** — часы
ЧЧ:ММ (без секунд) и дата по-русски. Дневной/ночной фон; ночью солнце заменяется луной
(и в текущей погоде, и в каждом часе прогноза).

Адрес в локальной сети: `http://10.10.10.118` (порт 80, IP компьютера из `ipad-2.md`).

## 2. Архитектура

```
iPad 2 ──HTTP──► home-dashboard (Docker, порт 80) ──HTTPS──► api.met.no
 (раз в 60 s)      server.py: кэш погоды в памяти,             (период refresh_sec
                   обновление по refresh_sec из config.json)    из config.json,
                                                               по умолчанию 600 s)
```

Ключевые решения и их причины:

| Решение | Причина |
|---|---|
| Погоду запрашивает сервер, не iPad | iOS 9: проблемы с современными TLS-сертификатами и CORS; API-ключ не светится на клиенте |
| Кэш погоды в памяти сервера | Переживает кратковременные сбои сети; iPad не ждёт внешний API |
| Один файл `index.html`, всё инлайн (CSS/JS/SVG) | ТЗ «одна страница»; ноль внешних запросов (CDN/шрифты недоступны/ненадёжны) |
| JS строго ES5, XHR вместо fetch | WebKit iOS 9 не знает fetch/let/const/стрелки/template literals |
| Раскладка на float + table-cell | Нет CSS Grid (iOS 10.3+), flexbox в iOS 9 глючный |
| Анимации только transform/opacity | GPU-композитинг; blur/тени/clip тормозят на A5 |
| MET Norway (api.met.no) | Бесплатно, без ключа (только User-Agent), почасовые данные, **доступен из РФ** — Open-Meteo оттуда заблокирован |

## 3. Файлы

- `server.py` — HTTP-сервер и прокси погоды (Python 3, **только stdlib**).
- `index.html` — вся страница (разметка + CSS + JS + SVG-иконки).
- `config.json` — настройки сервера (см. п. 4).
- `Dockerfile` — `FROM python:3.12-alpine`, копирует три файла, `EXPOSE 80`.
- `docker-compose.yml` — один сервис `dashboard`, `container_name: home-dashboard`,
  порты `80:80`, `restart: unless-stopped`.
- `README.md` — запуск и настройка iPad; `ipad-2.md` — паспорт устройства.

## 4. server.py

Конфигурация — `config.json` рядом с `server.py`, читается **один раз при старте**
(`load_config()`; правки применяются перезапуском контейнера):

```json
{
  "server_ip": "0.0.0.0",
  "location": {"name": "Москва", "lat": 55.7558, "lon": 37.6173},
  "refresh_sec": 600
}
```

- `server_ip` — на каком интерфейсе слушать (`0.0.0.0` — все). **В Docker имеет
  смысл только `0.0.0.0`**: у контейнера нет IP хоста, bind на него невозможен.
  Если адрес недоступен (`EADDRNOTAVAIL`), сервер не падает, а слушает `0.0.0.0`
  с предупреждением в лог — дашборд остаётся доступен по IP хоста. Ограничение
  по конкретному IP хоста делается в compose: `ports: ["10.10.10.118:80:80"]`.
  Порт в конфиг не вынесен: константа `PORT = 80`.
- `location` — `name` (подпись города на странице, уезжает клиенту в поле `city`)
  и координаты для MET Norway. Часовой пояс вывода фиксирован: константа
  `MSK = UTC+3` (Europe/Moscow без DST) — при смене региона править и её.
- `refresh_sec` — период опроса MET Norway, минимум 60 (`MIN_REFRESH_SEC`,
  защита от банов API). Уезжает клиенту в поле `refresh` — клиент считает по
  нему свой порог устаревания данных.
- Отсутствующий/битый файл и отдельные невалидные значения не роняют сервер:
  используется дефолт из `DEFAULT_CONFIG`, в stdout пишется предупреждение
  (видно в `docker logs`). Невалидные считаются: неправильный тип (в т.ч. bool
  вместо числа), `lat` вне ±90, `lon` вне ±180, `refresh_sec < 60`.
- `MET_URL` — `locationforecast/2.0/compact?lat=&lon=`. Провайдер **требует
  идентифицирующий `User-Agent`** (`USER_AGENT`), иначе банит. Ответ: почасовой
  `timeseries` (~9 суток; у каждой записи `instant.details` — `air_temperature`,
  `wind_speed` (м/с) и `next_1_hours.summary.symbol_code`), времена в UTC.
- `SYMBOLS`/`map_symbol()` — символ MET Norway → (иконка, описание). Суффиксы
  `_day`/`_night` срезаются (`split_symbol()`); `*andthunder` → `rain`/`snow`
  с описанием «Гроза» (по типу осадков). Иконок строго 4: `sun`, `clouds`,
  `rain`, `snow`. Неизвестный символ → `clouds`/«Облачно».
- `is_day`: из суффикса символа, а для нейтральных (`cloudy`, `fog`, `rain` без
  showers и т.п.) — `sun_is_up()`: приближение NOAA по lat/lon/UTC (±2 мин,
  полярные день/ночь учтены). У каждого часа прогноза свой `is_day` — клиент
  заменяет солнце луной.
- `feels_like()` — «ощущается как»: у MET Norway нет apparent_temperature,
  считается ветро-холодовой индекс Environment Canada для T≤10 °C и ветра
  >4.8 км/ч (не теплее фактической T), иначе = T.
- `fetch_weather()` — запрос с таймаутом 15 s, нормализация в плоский dict:
  ```json
  {"ok": true, "city": "Москва", "refresh": 600, "temp": 1, "feels": -3,
   "wind": 2.5, "icon": "clouds", "desc": "Пасмурно", "is_day": 1,
   "updated": "14:15", "fetched": 1762512000,
   "forecast": [{"time": "15:00", "temp": 1, "icon": "clouds", "is_day": 1}, ...]}
  ```
  `city`/`refresh` — зеркало `location.name`/`refresh_sec` из конфига (см. выше);
  присутствуют и в ответе при сбое сети, чтобы клиент знал город и порог свежести.
  `updated` — время текущей записи `timeseries`, переведённое из UTC в MSK
  (`parse_dt()` + `astimezone(MSK)`). Часовая метка данных, не момент обновления:
  надпись «обновлено в …» клиент строит по `fetched` (см. п. 5), `updated` —
  только запасной вариант, если `fetched` вдруг нет в ответе.
  `fetched` — epoch (`int(time.time())`) последнего **удачного** обновления;
  при сбое сохраняется вместе со старым кэшем — клиент по нему меряет возраст данных.
  **При ошибке сети старый удачный кэш сохраняется** (`if result["ok"] or not _cache.get("ok")`).
- `parse_forecast()` — 4 ближайших полных часа после `now` (записи `timeseries`
  почасовые и привязаны к полным часам; сравнение aware-datetime, не строк).
  Символ часа — `symbol_of()`: `next_1_hours`, иначе `next_6_hours` (вдали от
  «сейчас» первого может не быть).
- Потоки: основной — `ThreadingHTTPServer`; фоновый daemon-поток `refresher()`
  (fetch → sleep `refresh_sec`). Доступ к кэшу через `threading.Lock`.
- Эндпоинты: `GET /` и `/index.html` → страница; `GET /api/weather` → JSON;
  остальное → 404. Всем ответам ставится `Cache-Control: no-store`
  (iOS web-app агрессивно кэширует). Логирование запросов отключено (`log_message: pass`).
- **Важно:** `INDEX` читается из файла **один раз при старте процесса**. После правки
  `index.html` нужен перезапуск контейнера (`docker restart home-dashboard`),
  `docker cp` файла в запущенный контейнер недостаточно.

## 5. index.html

### Мета
`viewport` с `user-scalable=no`; `apple-mobile-web-app-capable=yes` +
`apple-mobile-web-app-status-bar-style=black-translucent` — fullscreen при запуске
с домашнего экрана, статус-бар поверх страницы (все 768 px доступны).

### Раскладка
Два `.half` (float left, width 50%, height 100%, `display: table`) с `.cell`
(`table-cell` + `vertical-align: middle`) — надёжное вертикальное центрирование
на старом WebKit. У левой половины `border-right` + **`box-sizing: border-box`
(обязателен!)** — без него 512+1+512 > 1024 и правая половина уезжает под экран
(найденный баг). `document.ontouchmove = preventDefault` — против «резинового» скролла.
Прогноз (`.w-forecast`) — тоже `display: table` + `table-layout: fixed` + `table-cell`
(4 равные колонки), отделён от текущей погоды `border-top`.

**Вертикальный бюджет левой половины (~713 px из 768):** город ~48 + иконка 205+8 +
температура 185 + описание ~47 + extra ~48 + upd ~41 + прогноз ~131. Главная иконка
уменьшена 235→205 именно ради прогноза; запас ~55 px не тратить без пересчёта.

### Темы
`body.day` / `body.night` — градиенты 160° (`#2f6fb3→#16324f` / `#141b3d→#05070f`),
каждый продублирован с `-webkit-linear-gradient`. Класс переключает клиент по `is_day`.

### JS (строго ES5)
- Часы: `tick()` по `setInterval(1000)`, запись в DOM **только при смене минуты**
  (`lastMinute`), массивы `DAYS`/`MONTHS` (месяцы в родительном падеже).
  Двоеточие — отдельный `span.colon` с CSS-анимацией `blink`, в JS не участвует.
- Погода: `fetchWeather()` — XHR на `/api/weather?t=<timestamp>` (cache-buster
  против кэша WebKit), `setInterval(60000)` + вызов при загрузке. `try/catch`
  вокруг `JSON.parse`. При `ok:false` — «нет данных».
- `renderWeather(w)`: выбор иконки; **логика луны на клиенте** —
  `if (icon === 'sun' && !w.is_day) icon = 'moon'`. Минус заменяется на
  типографский `−` (`fmtDeg`), десятичный разделитель ветра — запятая.
  Надпись «обновлено в …» — реальный момент обновления: `fmtFetched(w.fetched)`
  (epoch → локальное ЧЧ:ММ iPad, согласовано с часами справа); `w.updated`
  (часовая метка записи прогноза, стареет вместе с кэшем при обрыве) —
  только fallback.
- Иконка вставляется через `innerHTML` в `#wIcon` из словаря `ICONS`.
- Прогноз: `renderForecast()` заполняет `#wForecast` (внизу левой половины)
  4 ячейками «час + маленькая иконка + температура»; правило луны то же
  (`sun` + `is_day=0` → `moon`). Вызывается из `renderWeather()` только при
  наличии `w.forecast`; при `ok:false` прогноз не перерисовывается (остаётся
  прежний, как и весь кэш на сервере).
- Контроль свежести: `checkStale()` по `setInterval(1000)` — если
  `now - lastFetched > STALE_SEC`, на `#wUpd` вешается `stale` (красный
  цвет) и каждую секунду переключается `.dim` (opacity 1↔.2 через
  `-webkit-transition` 1 с) — мигание с периодом 2 с, как двоеточие часов,
  но через JS, а не CSS-keyframes: при сломанных анимациях остаётся красный
  цвет и жёсткое мигание. `lastFetched` = `w.fetched` из последнего ответа
  сервера, поэтому ловятся оба сценария: обрыв у iPad (`fetched` замирает)
  и сбой обновления на сервере (стареет кэш). Порог `STALE_SEC` =
  `w.refresh + 120` (приходит от сервера; до первого ответа — дефолт 720):
  запас 120 на опрос (60 с) и fetch (до 15 с), ложных миганий нет. При
  `ok:false` выставляется `forceStale` — красное сразу.
- Город: `w.city` из конфига пишется в `#wCity` (и `document.title`) через
  `textContent` (это текст, не разметка).
- Обрыв связи: `xhr.timeout = 30000` обязателен — без него зависшие XHR
  исчерпывают лимит соединений WebKit (~6 на хост), и восстановление не
  обнаруживается. Счётчик `netFailures`: при `>= 3` подряд неудач первый
  успешный ответ делает `location.reload()` — страница сама подтягивает
  свежий код и сбрасывает состояние после обрыва. Петли перезагрузки нет:
  после reload счётчик нулевой, а старый серверный кэш (ok:true) reload
  не вызывает.

### SVG-иконки (viewBox 200×200; рендер: основная 205×205, в прогнозе 44×44)
- `sun`: лучи — **вложенная `<g>`**: внешняя `transform="translate(100,100)"`,
  внутренняя `.rays` с `-webkit-transform-origin: 0 0` вращается (`spin`, 90 s).
  Так обходится ненадёжный `transform-origin` для SVG в старом WebKit — не менять
  без проверки на устройстве. Ядро — круг r=44.
- `moon`: круг r=76 + **SVG-маска** `#mcut` (чёрный круг-вырез) → серп. Дуги
  (path A-команды) дали нестабильную геометрию в тестах — оставить маску.
  Несколько лун на странице (главная + часы прогноза) дублируют `id="mcut"` —
  это не баг: маски идентичны, `url(#mcut)` берёт первую, рендер корректен
  (проверено скриншотом с 3 лунами).
- `clouds`: два облака (заднее `#8fa1b8`, переднее `#dbe3ee` с анимацией `drift`).
- `rain` / `snow`: облако `#c8d4e4` + 3 капли (`.drop`, анимация `fall`) / снежинки
  (`.flake`, `snowfall`) со сдвигом фаз через `animation-delay`.

### Правила анимаций (критично для iPad 2)
1. Только `transform`/`opacity`, все keyframes продублированы с `-webkit-`.
2. Базовое состояние элемента — `opacity: 1` (статичный fallback, если CSS-анимации
   не поддержаны), затухание задаётся внутри keyframes.
3. При `animation-delay` обязателен `animation-fill-mode: backwards`, чтобы элемент
   не «вспыхивал» базовым состоянием до старта анимации.
4. Иконки прогноза (44×44) **статичны**: `.f-icon svg * { animation: none }` гасит
   классы анимаций по специфичности — экономия GPU Apple A5. Базовое состояние
   `opacity: 1` (правило 2) делает их корректными статичными картинками.

## 6. Docker

- `Dockerfile`: `python:3.12-alpine` (~50 МБ), root внутри контейнера (биндинг 80
  порта), зависимостей нет. TZ в контейнере не нужна — московское время берётся
  из ответа API, часы идут на iPad.
- **Особенность окружения:** docker-клиент хоста по умолчанию указывает на
  незапущенный Docker Desktop (`desktop-linux`). Рабочий системный демон:
  `docker context use default`, далее обычный `docker compose up -d --build`.
- `docker-compose.yml` монтирует `./config.json:/app/config.json:ro` — правки
  конфига не требуют пересборки, только `docker restart home-dashboard`
  (конфиг, как и `index.html`, читается один раз при старте процесса).
- Сервер слушает `server_ip` из конфига (дефолт `0.0.0.0`) — дашборд доступен
  всей локальной сети (это осознанно, секретов нет). IP, которого нет на
  интерфейсах процесса (в Docker — любой IP хоста), не роняет сервер:
  fallback на `0.0.0.0` с warning в логе (см. п. 4).

## 7. Проверки (прогонять после изменений)

```bash
docker --context default compose up -d --build        # пересборка+перезапуск
curl -s http://127.0.0.1/api/weather                  # JSON погоды (ok:true)
curl -s http://127.0.0.1/api/weather | python3 -m json.tool  # forecast: 4 часа, у каждого time/temp/icon/is_day
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/
```

- JS-синтаксис (ES5): `node -e "new Function(require('fs').readFileSync('index.html','utf8').match(/<script>([\s\S]*)<\/script>/)[1])"`.
- Скриншот рендера ровно 1024×768:
  `google-chrome --headless --disable-gpu --no-sandbox --user-data-dir=/tmp/profX --window-size=1024,768 --screenshot=out.png http://127.0.0.1/`
  **`--user-data-dir` обязателен**, иначе headless конфликтует с запущенным
  десктопным Chrome и скриншот не пишется.
- Тест конкретной иконки/ночи: скопировать `index.html`, подменить в JS
  `var icon = w.icon;` → `var icon = 'rain';` (и `w.is_day ? 'day' : 'night'` → `'night'`),
  запустить копию `server.py` на другом порту (сменить константу `PORT`).
- Тест прогноза (в т.ч. луны в прогнозе): в копии `index.html` заменить тело
  `fetchWeather()` на вызов `renderWeather({ok:true, ..., forecast:[...]})` с
  фиктивными данными — так проверяются и ночной фон, и дублирующийся `id="mcut"`.
- **Не проверено на реальном iPad 2** — вся совместимость обеспечена кодом
  (ES5, префиксы), но живой прогон на устройстве обязателен при сдаче.

## 8. Известные грабли (не наступать повторно)

1. После `docker cp index.html` страница не обновится — нужен restart (кэш в памяти, п. 4).
   То же с `config.json`: читается один раз при старте — `docker restart home-dashboard`.
2. При запуске нескольких тестовых копий `server.py` менять `PORT` в каждой —
  все читают одну константу.
3. `pkill -f <подстрока_команды>` убивает и собственный shell, если подстрока
  есть в его cmdline — убивать по PID (`kill $(cat pidfile)`).
4. `float`-раскладка чувствительна к 1 px: любые border/padding у `.half` — только
  с `box-sizing: border-box`.
5. iOS web-app кэширует жёстко: `no-store` на всех ответах + `?t=` в XHR — не удалять.
6. Вертикальный бюджет левой половины ~713 px из 768 (см. п. 5 «Раскладка»): любой
   новый блок/увеличение шрифта — только с пересчётом, иначе контент уползёт за экран
   (скролл запрещён, обрезку не видно до проверки скриншотом).
